# LocalRack v1.4.1

A fix for services failing to follow `node_modules` junctions after LocalRack updates itself.

## Fixes

- **Services could no longer follow junctions after an update.** When LocalRack was relaunched by the installer's "Launch LocalRack" step, it inherited Windows Redirection Guard from the elevated setup process, and so did every service it started. Windows then refused to follow junctions created by a normal user, such as the workspace links pnpm and npm put in `node_modules\@scope\...`. Node reported `UNKNOWN: unknown error, stat`, and bundlers such as Vite and Rollup reported that they could not resolve a workspace package. The installer now starts LocalRack through Explorer, so it has the same parent as a launch from the Start menu.

## Install

Download one of these below:

- **Installer (recommended):** `LocalRack-v1.4.1-win-x64-setup.exe`. Run it and approve the administrator prompt.
- **Portable:** `LocalRack-v1.4.1-win-x64.exe`. A single self-contained executable; nothing is installed.

Both are for 64-bit Windows 10 and 11, and neither needs .NET installed.

**Coming from an earlier version?** Your projects and settings carry over automatically. LocalRack can offer this update itself from the startup check, or you can install it manually. Exit the running copy before installing.

**Already on 1.3.0 or 1.4.0 and seeing the junction errors?** Updating to 1.4.1 fixes it, because the new installer is the one that relaunches LocalRack. Until then, quit LocalRack from the tray and start it again from the Start menu.

To verify a download, compare its SHA-256 hash with `SHA256SUMS.txt`:

```powershell
Get-FileHash .\LocalRack-v1.4.1-win-x64-setup.exe -Algorithm SHA256
```

## Known limitations

- Log lines already on screen keep their old colours when you switch theme. New lines use the new palette.
- Services within a group are ordered inside their project; you can't interleave services from different projects.
- The installer and the executable are not code-signed yet, so Windows SmartScreen may show "Windows protected your PC" on first run. Choose **More info**, then **Run anyway**. The update check verifies a checksum published in the same release, which protects against corrupted downloads but is not a substitute for code signing.
